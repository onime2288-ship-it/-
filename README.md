# vedit

面向品牌宣传片的视频剪辑工作流。用 YAML 描述剪辑，用 ffmpeg 执行。

## 它解决什么问题

一条片子手剪更快。这套东西是给**反复要出片**的场景用的：
品牌调性定义一次，以后每条片子只写镜头表；改一个参数全片重渲；
一套剪辑一次导出多种画幅。

## 安装

只依赖 ffmpeg 和 Python 3.11+，不需要 OpenCV/numpy。

```bash
brew install ffmpeg          # macOS
pip3 install pyyaml
```

## 从素材库自动找素材

素材库通常几十 GB，人工翻一遍不现实。分两步：

```bash
# 1) 扫描：切镜头、评估画质、挑推荐入点、生成联系表
python3 -m vedit scan /Volumes/外接盘/素材库

# 2) 看 contactsheet.jpg，按编号挑镜头
```

扫描会对每个镜头自动算出：

| 指标 | 用途 |
|---|---|
| 清晰度 | 虚焦的直接标出 |
| 曝光 | 过曝、死黑标出 |
| 运动量 | 区分静止 / 缓慢运镜 / 剧烈晃动 |
| 推荐入点 | 镜头内最实最稳的一段 |

三个指标共用**一次解码**算出，4K 素材下解码是瓶颈，分开跑会慢三倍。

扫描是增量的：文件大小和修改时间没变就跳过，改天补拍了再跑一次很快。

### 一个反直觉的点

清晰度的**绝对值不能跨镜头比较**。实测数据：

```
大景深茶山空镜（对焦准）      5.84
浅景深泡茶特写（对焦准）      2.73
轻微虚焦的茶山               4.48
```

浅景深特写天生高频细节少，分数比轻微虚焦的空镜还低。所以设全局阈值
会把特写全误杀——而特写恰恰是品牌片最需要的。

因此：**「哪一段最实」只在镜头内部比**，绝对值只用来砍极端废片。

## 出片

```bash
python3 -m vedit run film.yml -v
```

## 命令

| 命令 | 作用 |
|---|---|
| `scan` | 扫描素材库，建索引，出联系表 |
| `sheet` | 从已有索引重新生成联系表 |
| `probe` | 看素材信息 |
| `analyze` | 预估去静音效果 |
| `run` | 按 recipe 出片 |
| `retime-srt` | 剪辑后给字幕重新对轴 |
| `steps` | 列出可用步骤 |
| `init` | 生成 recipe 模板 |

## 设计要点

**时间线与镜头表分离。** `timeline.py` 处理「一个素材剪掉哪些段」（口播类），
`shots.py` 处理「多镜头排列加溶解」（品牌片类）。两套模型各管各的场景。

**编码只发生一次。** 所有分析步骤只修改时间线，不碰画面。叠加十个剪辑
步骤和只剪一刀，画质损失与耗时相同。

**调色不用 LUT。** LUT 是黑盒，改不动也看不懂。这里每个参数都有名字，
想让绿色再灰一点就调 `saturation`，所见即所得。

## 已知的 ffmpeg 坑

- `drawtext` 没有字距参数，拉开字距只能手动往字符间插空格
- 中文必须显式传 `fontfile`，只给家族名会渲染成方框
- 文案走 `textfile=` 而非 `text=`，绕开中文标点的转义问题
- `loudnorm` 会把采样率抬到 192kHz，后面要跟 `aresample` 还原
